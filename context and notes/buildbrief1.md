## 1. Goal

A live-demo web app for use in sales presentations. It shows clients how AI changes the customer journey when buying products. Single scenario: buying Bluetooth earbuds. The app must look polished, run a real LLM on the backend (with live web search), and end in a working Stripe test checkout.

**Framing:** This is a demo, not a production webshop. Functionality outside the defined happy path does not need to work. Visual polish and a smooth live-presentation flow are priority #1.

## 2. Tech Stack (fixed — no alternatives)

- **Framework:** Next.js 14 (App Router), TypeScript, React 18
- **Styling:** Tailwind CSS + shadcn/ui. Font: Inter. Dark mode default.
- **Animation:** Framer Motion (view transitions, card animations, AI thinking states)
- **Icons:** lucide-react
- **State:** React Context + useReducer for cart. No Redux.
- **LLM provider:** Anthropic Claude API, model `claude-sonnet-4-6`, with the `web_search_20250305` server tool enabled

- **Hosting:** Vercel
- **Package manager:** pnpm
- **Node version:** 20 LTS

No database. No auth. Cart state lives in-memory via React Context.

## 3. Data Types

No hardcoded product catalog. Products are fetched live by the AI via web search. The feature schema below is fixed; the AI fills in values or returns `null` — never fabricates.

```typescript
type ProductFeatures = {
  batteryLifeHours: number | null;
  bluetoothVersion: string | null;   // e.g. "5.3"
  noiseCancelling: boolean | null;
  waterResistance: string | null;    // e.g. "IPX4"
  weightGrams: number | null;
};

type LiveProduct = {
  id: string;                        // generated uuid per search
  name: string;
  brand: string;
  price: number;                     // raw, as found
  currency: string;                  // default "USD"
  imageUrl: string | null;           // from web search, nullable
  sourceUrl: string;                 // where AI found the product
  features: ProductFeatures;
  description: string;
  customerSentiment: string;         // short, "customers mention…"
  rationale: string;                 // 2–3 sentences
  isRecommended: boolean;
  recommendationReason: string | null;
};

type CartItem = {
  product: LiveProduct;
  quantity: number;
};
```

Null values render as `—` in the UI.

## 4. Screens & Flow

Single-page application with view transitions, no page reloads. Four sequential screens.
### Screen 1 — Landing / Prompt

- Full-screen hero, centered.
- Heading: `What are you shopping for?`
- Subheading: `Describe what you need. Our AI will help you find it.`
- Large multi-line auto-expanding textarea. Placeholder: `e.g. I'm looking for the best earbuds for working from home…`
- Primary button: `Find products`
- Four suggestion chips below input: `Best for work calls`, `Noise cancelling under $200`, `Long battery life`, `Premium sound quality`. Clicking fills the textarea.
- Submit → transition to Screen 2.
### Screen 2 — Clarifying Questions

- Header shows the user's original query as a quote.
- 3–5 clarifying question cards generated by the LLM.
- Each card:
    - Question title
    - 3–4 clickable answer chips (single select)
    - Selected chip highlights with cyan accent
- All questions are optional.
- `Continue` button bottom right — enabled after at least 1 answer, or via `Skip all` link.
- Shimmer skeleton cards while LLM generates.
- Continue → transition to Screen 3.
### Screen 3 — Product Results

- Header: AI summary in 1–2 sentences, streamed with typewriter effect.
- Grid of 3–5 product cards (responsive: 1 col mobile, 2 tablet, 3+ desktop).
- Each card:
    - Product image (from web search) or placeholder SVG (earbud icon on cyan gradient) if `imageUrl` is null or fails to load
    - Product name + brand
    - Price with currency (e.g. `$299 USD`)
    - Feature table: Battery Life, Bluetooth Version, Noise Cancelling, Water Resistance, Weight. Null → `—`
    - AI-generated rationale (2–3 sentences) including a small caveat from customer sentiment
    - `Add to cart` button
- **1 or 2 cards get an "AI Recommended" badge** in cyan with subtle glow. Tooltip on hover explains why.
- Sticky mini-cart icon top right with item count badge. Click → opens cart drawer.
- `Continue to checkout` button at bottom, enabled when cart has ≥1 item.
### Screen 4 — Checkout

- Stripe hosted Checkout (test mode) via redirect. Do not build a custom checkout UI.
- Server creates a Checkout session with inline `price_data` line items (no pre-created Stripe products).
- Success URL → `/success` page: `Payment successful (test mode)` + `Start new demo` button that resets all state and returns to Screen 1.
- Cancel URL → back to Screen 3 with cart intact.

## 5. API Routes

All routes live under `app/api/`.
### 5.1 `POST /api/clarify`

**Input:**

```json
{ "query": "string" }
```

**LLM task:** Generate 3–5 clarifying questions with 3–4 options each. Use Claude `tool_use` to enforce strict JSON output.

**Output:**

```json
{
  "questions": [
    { "id": "q1", "question": "string", "options": ["string", "string", "string"] }
  ]
}
```

**System prompt:**

> You are a shopping assistant for Bluetooth earbuds. Ask 3–5 short, concrete questions to clarify the user's needs. Focus on use case, budget, and key features. Respond in JSON only.

### 5.2 `POST /api/recommend`

**Input:**

```json
{
  "query": "string",
  "answers": [{ "question": "string", "answer": "string" }]
}
```

**LLM task:** Use Claude with the `web_search_20250305` server tool (max 5 uses) to find 3–5 current Bluetooth earbud products matching the user's needs. Return structured JSON via `tool_use`.

**Tool config on the Claude API call:**

```json
{
  "model": "claude-sonnet-4-6",
  "tools": [
    { "type": "web_search_20250305", "name": "web_search", "max_uses": 5 }
  ],
  "max_tokens": 4096
}
```

**System prompt:**

> You are a shopping AI for Bluetooth earbuds. Use web search to find 3–5 current products matching the user's needs. For each product, extract: name, brand, price (raw, as found), currency, an image URL, and the following features: batteryLifeHours, bluetoothVersion, noiseCancelling, waterResistance, weightGrams. Use `null` for any field you cannot verify — never fabricate values. Write a 2–3 sentence rationale per product including a small caveat drawn from customer sentiment. Mark at most 2 products as `isRecommended: true`. Respond strictly in JSON matching the provided schema.

**Output:**

```json
{
  "summary": "string (1-2 sentences)",
  "recommendations": [ /* array of LiveProduct */ ]
}
```

**Streaming:** use Server-Sent Events for the progressive "AI thinking" UI. **Timeout:** 60 seconds. **No caching** between runs — every demo should be fresh.

### 5.3 `POST /api/create-checkout-session`

**Input:**

```json
{
  "items": [
    { "product": { /* LiveProduct */ }, "quantity": 1 }
  ]
}
```

**Output:**

```json
{ "url": "https://checkout.stripe.com/..." }
```

Server maps each cart item to a Stripe line item using inline `price_data`:

```javascript
{
  price_data: {
    currency: item.product.currency.toLowerCase(),
    product_data: { name: `${item.product.brand} ${item.product.name}` },
    unit_amount: Math.round(item.product.price * 100)
  },
  quantity: item.quantity
}
```

## 9. Error Handling

- LLM call fails → toast `AI is temporarily unavailable` + retry button. Do not crash.
- LLM returns invalid JSON → 1 retry, then fall back to `lib/fallbacks.ts` default responses.
- Image URL fails to load → `onError` swaps to placeholder SVG.
- Stripe fails → toast + stay on Screen 3.
- All errors logged via `console.error` with clear labels.
